# Remask Desktop

**本地优先的 AI PII 隐私保护网关。**

[English](README.md)

Remask 位于 AI 客户端与 AI 服务商之间。它会在请求离开设备前识别敏感信息，将其替换为安全占位符，并可在支持的响应中还原被保护的内容。

无论是 AI 编程助手、桌面应用、浏览器、SDK、脚本还是内部工具，都可以通过 Remask 使用 AI，而不必把未经处理的个人信息或机密数据直接发送给 AI 服务。

## 为什么使用 Remask

AI 工作流中经常会出现姓名、邮箱、账户信息、访问凭证、客户资料、源代码以及其他敏感上下文。每次手动删除这些信息既耗时，也很容易遗漏。

Remask 为不同 AI 工作流提供统一的隐私保护层：

- 敏感数据在本机完成识别和脱敏，然后才会发送出去。
- 现有 AI 工具可以通过熟悉的 API Base URL 或本地代理接入。
- 不同应用、服务商和团队流程可以使用一致的保护策略。
- 默认无需暴露原始敏感内容，也能检查请求保护情况。

## 核心功能

### 本地 PII 识别与脱敏

Remask 结合本地识别模型与确定性规则，可识别的信息包括：

- 姓名、电话号码、电子邮箱和地理位置
- 账户号码、银行卡信息和政府签发的证件信息
- 用户名、密码、API Key、密钥和 PIN 码
- IP 地址、设备标识、网址以及其他自定义内容

受保护的请求发送给 AI 服务商之前，识别到的内容会被替换为带类型的占位符。

### 两种 AI 流量保护方式

**API 网关** —— 在 SDK、脚本、服务或其他 API 客户端中，将 Base URL 替换为 Remask 提供的地址。Remask 会根据所选服务商和保护策略处理请求，然后转发至上游。

**代理网关** —— 让现有应用通过本地 HTTP/HTTPS 或 SOCKS5 代理连接。添加需要保护的目标域名后，Remask 会在保留应用原始目标地址的同时，对匹配的 AI 流量进行检查和脱敏。

### 安全启动应用

可以直接从 Remask 启动受支持的工具，所需的代理和证书环境会自动配置。快捷启动适用于 Codex、Codex CLI、Claude Code、OpenCode、浏览器、终端以及其他已安装应用等常见 AI 开发场景。

保护范围仅限通过 Remask 启动的应用，无需修改全局 Shell 或系统代理设置。

### 灵活的保护策略

- 单独启用或停用不同 PII 类型。
- 通过正则表达式添加组织内部的专用标识规则。
- 选择是否对系统消息和历史 AI 回复进行脱敏。
- 在确实需要发送原文时，明确暂停全局保护。
- 在支持的 AI 响应中选择是否还原被保护的内容。

### 本地可视化与控制

桌面仪表盘会展示请求量、已保护实体、处理延迟、Token 用量和最近活动。内置的脱敏测试可以在连接应用前，先用本地文本验证保护策略。

通过请求日志可以确认哪些字段已被保护，以及实际发送给 AI 服务的内容。日志内容、保留时间和清理方式均可配置。

### 服务商与模型管理

可以配置多个 AI 服务商，将托管凭证保留在本机，切换本地识别模型，并选择可用的推理设备。Remask 还支持针对不同服务商格式配置自定义请求适配方案。

### 桌面端体验

- 系统托盘控制与可选的开机启动
- 用于保护 HTTPS 流量的本地 CA 证书引导安装
- 英文、简体中文、日文和德文界面
- 提供 macOS 与 Windows 安装包，并支持从源码构建 Linux 版本

## 工作方式

```text
AI 应用或 SDK
      |
      v
Remask 在本机识别并脱敏 PII
      |
      v
AI 服务商收到受保护的内容
      |
      v
Remask 可在响应中还原占位符
```

AI 服务商仍会收到请求中的非敏感内容和生成的占位符。在正常的受保护工作流程中，识别到的原始敏感值会留在本机。

## 常见使用场景

- 使用 AI 编程工具时，避免泄露凭证、内部主机地址或粘贴到提示词中的客户数据。
- 在个人信息完成脱敏后，让 AI 总结客服工单、文档或 CRM 导出数据。
- 在兼容 OpenAI 的 SDK 和内部 AI 应用前增加统一隐私保护层。
- 让多个 AI 服务商遵循同一套 PII 保护策略。
- 通过受保护的请求历史进行隐私审查和问题排查。

## 快速开始

1. 从 [GitHub Releases](https://github.com/remask-dev/remask-desktop/releases/latest) 下载最新安装包。
2. 打开 Remask，使用示例文本确认内置脱敏测试正常工作。
3. 选择一种接入方式：
   - 添加 AI 服务商，并复制其 API 网关 Base URL。
   - 添加受保护目标，并通过代理网关连接。
   - 使用快捷启动，在受保护环境中打开应用。
4. 发送测试请求，然后在**请求日志**中检查保护结果。

## 隐私边界

只有在全局保护已启用，并且请求匹配已配置服务商或受保护目标时，Remask 才会处理该流量。未匹配的代理流量会被透明转发，不会进行检查或脱敏。

对于 HTTPS 代理保护，Remask 使用本地 CA 证书，其私钥始终保留在设备上。托管的服务商凭证保存在本机，并且不会写入请求日志。调试日志或原始内容日志可能包含敏感信息，只应在确有需要时启用。

Remask 可以降低 PII 意外泄露的风险，但仍应作为整体安全与数据治理体系中的一层保护措施使用。
